## What Went Well

### 1. Harvester Framework Scales for Third Epic
The Scanner → Parser → Filter/Detector → Repository → Events pattern adapted from research scanning (Epic 2) through leads (Epic 5) to regulatory monitoring with zero architectural rework. All 10 stories built on the same foundation.

### 2. Pre-Submission Checklist Working
Created between Epic 5 and Epic 6, the pre-submission checklist reduced CR fix rate from 100% to 80%. Story 6-8 achieved the first-ever clean review (zero issues). This proves the process improvement works.

### 3. `datetime.utcnow()` Problem Finally Solved
After being flagged in Epic 4 retro, carried through Epic 5, and targeted for CI linting (never done) — the problem was solved by habit formation. Team agreement #2 from Epic 5 worked where tooling didn't.

### 4. RegulatoryEventEmitter — Organic Architecture
A pub/sub event system (asyncio.Queue) emerged naturally across 6 stories, providing 15+ event types for decoupled communication between regulatory monitors, alert systems, and evidence collection.

### 5. Three-Layer Immutability (Story 6-8)
Application guard (ImmutableEvidenceError) + PostgreSQL trigger + file system chmod — production-grade evidence integrity that serves as a blueprint for any future immutable storage needs.

### 6. Zero Production Incidents (Again)
Clean epic with no production issues across all 10 stories. Graceful degradation applied consistently.

### 7. Hybrid Regex+LLM Pattern (Story 6-6)
Novel two-phase approach: free regex pre-filter (fast, catches obvious patterns) → LLM classification (accurate, tier="generate"). Applicable to any content analysis pipeline.

### 8. Epic 5 Retro Action Items — 2/3 Completed
Significant improvement from 0/3 in the prior cycle:
- Pre-submission checklist: **DONE** (docs/pre-submission-checklist.md)
- RetryMiddleware pattern docs: **DONE** (docs/retry-middleware-patterns.md)

## Challenges Encountered

### 1. N+1 Queries Still Recurring
Found in Stories 6-7 and 6-10. Despite being a known pitfall from Epic 5, N+1 query patterns still slip through. The pre-submission checklist doesn't explicitly call this out.

**Root Cause:** Pre-submission checklist focuses on code style issues (exports, datetime, types), not performance patterns.

### 2. CRITICAL Security Issue — SQL Injection via getattr (Story 6-9)
The searchable evidence database used `getattr` on user-supplied sort field names, creating a potential SQL injection vector. Caught in code review, not in development.

**Root Cause:** No explicit security review step for stories handling user input in database queries.

### 3. `__all__` Exports Still Slipping (Story 6-6)
Despite being a team agreement since Epic 5, missing `__init__.py` exports were caught again in 6-6.

**Root Cause:** Improved (1 story vs. all 5 in Epic 5) but not eliminated. Needs to be more prominent on checklist.

### 4. RegisteredAgent vs RegisteredService Confusion (Story 6-6)
Story 6-6 initially used RegisteredService for the claim extraction engine, which should have been RegisteredAgent (it uses LLM tier). No documentation exists for when to use which.

### 5. Later Stories Accumulate More Issues
| Stories | Avg CR Issues |
|---------|---------------|
| 6-1 to 6-5 | ~8.6 |
| 6-6 to 6-10 | ~6.0 |
| 6-10 (final) | 9 (2 CRITICAL) |

Story 6-10 had the most issues including 2 CRITICALs. Pattern suggests final stories may need extra scrutiny.

### 6. Code Review Fix Rate 80% — Better but Above Target
Target was <50% (from Epic 5 retro). Achieved 80% — meaningful improvement but not yet at target. The one clean review (6-8) shows it's possible.

## Significant Discoveries

### 1. Hybrid Regex+LLM Pattern
Two-phase content analysis: regex pre-filter (free, instant) → LLM classification (accurate, tier="generate"). Applicable beyond health claims to any content classification task. Should be documented as a reusable pattern.

### 2. RegulatoryEventEmitter Architecture
Pub/sub event system emerged organically across Stories 6-1, 6-3, 6-4, 6-7, 6-8, 6-9. Provides 15+ event types. This event-driven pattern may inform Epic 7's analytics pipeline design.

### 3. Three-Layer Immutability
Application + Database + File System protection layers. Production-grade immutable storage pattern applicable beyond evidence to any audit-critical data.

### 4. Security Review Gap
CRITICAL SQL injection risk found in 6-9 via `getattr` on user-supplied sort fields. Indicates need for explicit security review in stories handling user input — process gap, not skill gap.
