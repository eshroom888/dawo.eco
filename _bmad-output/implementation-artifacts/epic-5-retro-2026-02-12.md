## What Went Well

### 1. Harvester Framework Pattern Scales
The Scanner -> Harvester -> Transformer -> DuplicateChecker -> Repository pattern from Epic 2 adapted beautifully to lead discovery. Story 5-1 established the lead pipeline variant, and all subsequent stories built upon it naturally.

### 2. Strongest Test Coverage Yet (642 Tests)
Protocol-based dependency injection enabled clean, comprehensive mocking. Story 5-3 peaked at 181 tests. Every story tested both success and failure paths consistently.

### 3. GDPR Compliance Built In From Day One
Starting with GDPR considerations in Story 5-1 (source tracking, activity logging) and building through to the full GDPR pre-send validator in Story 5-4 (personal email blocking, contact spacing, max outreach limits) meant compliance was never an afterthought.

### 4. Full B2B Pipeline - Real Business Value
From zero lead management to a fully automated discovery-to-send-to-track pipeline. Norwegian personalized outreach, brand voice validation, Gmail API integration with rate limiting, and a Kanban-style dashboard.

### 5. Zero Production Incidents
Clean epic with no production issues. Graceful degradation pattern applied consistently across all pipelines.

### 6. Async Google API Pattern Discovery
Story 5-4 discovered the pattern for wrapping synchronous `googleapiclient` calls in `asyncio.run_in_executor()` - an elegant solution that prevents event loop blocking.

## Challenges Encountered

### 1. Code Review Fix Rate: 100% (No Improvement from Epic 4)
All 5 stories required at least one round of fixes post-review. Common issues:
- Missing `__init__.py` exports (every story)
- `datetime.utcnow()` deprecation (caught in 5-5)
- Type annotation gaps
- Story 5-5: 7 issues (H1 double activity logging, H2 fragile field mutation, M1 N+1 query, M2 in-memory date filtering, M3 integration test flow, M4 missing exports, L1 type hints, L3 datetime UTC)

**Root Cause:** Epic 4 action items (pre-submission checklist, deprecation linting) were never implemented.

### 2. Epic 4 Action Items Not Completed (0/3)
| Action Item | Status |
|-------------|--------|
| Pre-submission code review checklist | Not Done |
| Add deprecation linting to CI | Not Done |
| Mock verification pattern documentation | Partially Done |

**Root Cause:** Action items that require creating new artifacts don't happen unless explicitly scheduled. Team agreements that become habits (like testing both success+failure) do stick.

### 3. Pipeline Auth Error Detection Pattern
Story 5-4 uncovered a subtle pattern: `RetryMiddleware` returns `RetryResult` with `is_incomplete=True` on failure - it never raises exceptions. The `GmailSendService` catches `GmailAuthError` internally and returns a `GmailSendResult`. The pipeline must inspect `result.error` for auth errors to know when to stop the entire batch. This pattern is undocumented and could trap future developers.

### 4. Test Count Decline in Later Stories
Test counts: 112 -> 133 -> 181 -> 128 -> 88. The decline correlates with:
- Story 5-4 introduced OAuth2/external API complexity (fewer but more complex tests)
- Story 5-5 was full-stack (Python + React + TypeScript) with different testing velocity

### 5. Integration Test Coverage Gap
Stories 5-4 (16 integration tests) and 5-5 (7 integration tests) have lower integration coverage compared to earlier stories, though unit test coverage remains strong.
